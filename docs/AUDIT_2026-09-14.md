## 一、有问题的实现（按严重度）

### 高

1. **`GameTag.PREPARING` 版本兼容崩塌** — `hsbot/store.py:540,792`
   `PREPARING`(=4726)/`PREPARE`(=4354) 是 hearthstone **9.20.12** 才加入的枚举成员；
   requirements 下限 9.20 → 任何非 ZONE/CONTROLLER/COST 的 TagChange（伤害/血量/
   护甲/攻击）在 elif 链求值 `GameTag.PREPARING` 时抛 AttributeError。
   测试 22 挂；live 下被 `_process_tree` 逐包 try 吞掉（watcher.py:595-597）——
   英雄血量变动、预备等衍生事件**静默丢失** + 控制台刷异常。
   修法：钉 `hearthstone>=9.20.12`，或沿 consts.py:27 先例 `getattr(GameTag,"PREPARING",4726)`。

2. **CREATE_GAME 边界动作时序错乱（跨局同批）** — `hsbot/watcher.py:261-264` + `hsbot/pipeline.py:99-102`
   重置 manager / 重置 game_lines 在"喂行时"执行，而上一局的包应用与终局导出在
   `_after_batch` 才跑。两种实测表现：
   (a) 上一局 store 未建时下局 CREATE_GAME 先清 manager → 玩家级 TagChange 解析失败
   → **turn_start/game_end 全不发**：无终局快照、无训练导出、无自动训练（整局静默丢）；
   (b) 上局终局行与下局 CREATE_GAME 同批 → `_export_training` 取 `game_lines` 已被
   重置为下局头部 → **原始 .power.log 切片被覆写**（实测 40 行→2 行，永久丢失）。
   触发面：live 轮询罕见；**`_attach` 5000 行追平批常见**。语料库现存 11 个
   `.power.power.log` 异常工件（.gitignore 自注"待修导出端"）即此族实证。
   换边局钉子测试只走 `run_replay`（批永不跨局），此路径零覆盖。

3. **T1 engines 从未接线——引擎循环抽牌通道生产不可达** — `hsbot/analysis.py:270-272`
   `initial_state(...)` 只传 known_draws，`engines` 恒默认 0；全仓无生产代码从场面推导
   cast_draw 引擎数。拍卖师在场施法不抽牌、台账顶牌队列永不消耗——奇迹德 OTK 核心
   引擎整条线系统性漏报（安全方向，但 PLAY_ADVICE §6.8 宣称"engines 循环抽牌"已
   落地验收 ✓，与事实不符）。

4. **board_atk 无攻击合法性口径——最现实的假阳性源** — `hsbot/analysis.py:273` + `hsbot/store.py:230-232`
   场攻 = 我方 PLAY 区随从攻击力总和，不判敌方嘲讽挡脸、召唤失调、冻结、本回合已攻击。
   失败局面：敌场任一嘲讽，我直伤 8 + 场攻 8、敌 12 血 → 报"可斩 8+8≥12"，实际不可。
   且"每次打出后批尾重算"会让刚下场的失调随从攻击力立即计入。
   违反 §6.7"可斩只可能漏报不可能误报"的承诺。

5. **LR AUC 门控永远无法通过（死代码）** — `trainer/mulligan.py:350-355` + `hsbot/mulligan_ai.py:451-452`
   `_save_version` 写 model.json 前剥掉 metrics（进 meta.json），`advise` 却从 model.json
   读 `test_auc` → 恒 None → `lr_ok` 恒 False → LR 拍板权分支不可达。
   设计 §2.3「AUC≥0.55 才有拍板权」被实现杀死。测试没抓到是因为用内联 dict 绕过了
   落盘-回读链路。

6. **CostDown `next:` amount 被当"张数"而非"面值"（实跑验证的假阳性）** —
   `planner/simstate.py:62-63,91-92` vs `planner/pieces.py:29` 注释
   disc_next=N 按"每张 -1 消耗 N 次"结算。伺机待发族"下一法术-3"构造：
   手牌[减费牌0费, 2费2伤×3]、mana 3 → DFS face=6 报可斩；真实语义（-3 只作用一张）
   最多 4 伤。`tests/test_planner.py:167-175` 反而把错误语义固化成断言。

7. **自动训练子系统一串问题** — `hsbot/watcher.py:166-216` + `trainer/mulligan.py:342-381`
   - `auto_train_models` 是死开关：不在 config DEFAULTS/_FIELDS，config.yaml 写了也被
     白名单**静默丢弃**，`getattr(...,True)` 恒真——后台三条训练子命令无法关闭；
     且只受 `_live` 门控，用户关掉 `auto_training`（不导语料）后每局终仍照常空转重训；
   - 失败被"完成"掩盖：子进程失败仅 log.warning（stderr 末 300 字符），最终无条件
     emit「后台增量训练完成： 留牌模型 无变化」——失败/无变化不可区分（违 R12）；
   - daemon 线程退出不清理子进程：孤儿最长再跑 900s；立刻重启再触局终 → 并发
     `_save_version`（max+1 无锁 + 裸 write_text 非原子）→ 同写一个 vNNN 产物交错；
   - 相对路径错位：`--data-dir` 传相对 "data"、子进程 cwd=仓库根；bot 从非仓库目录
     启动时，语料/模型目录全链路静默错位（训练照跑、建议永远用不上新模型）；
   - 每局终 `material` 全量重放所有 .power.log 切片（当前 77 片约 80 万行）+ GBM
     全量重拟合，代价随语料线性增长，而 value.pkl 全仓无消费者。

### 中

8. **damage 族 scope="all" 规则基本不可达 + pieces 不读 scope** — `hsbot/effects.py:151-155`
