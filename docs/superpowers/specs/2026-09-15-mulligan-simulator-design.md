## 0. 前提的形式化与实证

**自闭性三条件**(用户主张的形式化;任一破坏则本设计退化、走 v3 原路径):

1. 胜利条件不依赖对手互动:凑齐组件 → 启动 → 胜,启动谓词只含我方手牌/
   场面/费与敌方**数值**(血甲),不含敌方行为;
2. 卡组 0 变化:同一 30 张,牌表完全已知;
3. 启动即胜:P(胜│启动) ≈ 1(由真实语料验证,§6 结果层)。

**实证(2026-09-15 语料终态:85 局)**:

| 证据 | 数值 |
|---|---|
| 奇迹德占比 | 83/85 局(另 2 局"自定义 萨满祭司",走兜底级联不覆盖) |
| 奇迹德 deck_code 种类 | **1 种**(0 变化成立) |
| 当前 schema 语料 | 60 局(含 game_id/heroes,重放推导可用) |

**残余例外**(自闭性的边界,启动谓词必须保守处理):冰甲/嘲讽抬高斩杀线、
奥秘/脏鼠式破坏打断组件、对手护甲动态。处理:敌方有效血甲不取点值而取
**分布**(§4),分位数敏感性分析;不做对手行为模型(§11)。

## 1. 核心分解:留牌价值的三因子

```
P_win(keep集) = Σ_K  P(启动≤K │ keep集) · P(存活至K) · P(胜│启动于K)
```

| 因子 | 来源 | 量级 |
|---|---|---|
| P(启动≤K│keep集) | **蒙特卡洛 rollout(本设计)**:抽样牌序 × 脚本策略推演,启动谓词判定 | 无限(计算,非估计) |
| P(存活至K) | 真实语料经验曲线:按对手职业分层的"我的第 K 回合仍存活"频率 | 85 局可估(一维量) |
| P(胜│启动于K) | 真实语料验证应 ≈1;偏离即模拟器现实差距警报(§6) | 同上 |

关键认知:"大量数据"在此**不是训练素材而是频率逼近本身**——1k 个牌序 × 2ⁿ
候选集的启动结果表就是精确概率的估计,没有带噪标签、没有过拟合、没有
泛化问题。真实语料的角色从"监督信号"变为"校准与验证"(§6)。

## 2. 架构:四级级联(修订 v3 §7)

```
评分(keep集) ←─ 模拟器(计算) ─ TabPFN v2(拟合) ─ LR ─ 统计表
                    │ 0 变化卡组 + pieces 完备 + 校准通过
                    └─ 任一不满足 → 逐级降级(模型互不信任哲学不变)
```

- **模拟器为第一后端**,仅服务 0 变化卡组(当前=奇迹德;萨满 2 局自动走
  v3 原路径,级联天然分流,无需特判);
- v3 的 Q 模型(阶段一)**保留**,但角色收窄为 T2 打牌节点排序(v3 §4 原样),
  不再作为留牌标签的必经来源;
- TabPFN v2 / TabICL v2 对照、三级兜底、AUC 门控哲学全部不变。

## 3. 多回合 rollout(纯函数,新增 planner/rollout.py)

复用 SimState/play 全部语义(减费/disc_next 一次性/引擎循环/法强逐段,
COMPILER_VERSION 7 的效果 IR)。**与现有 dfs 的一处语义分歧,单列条款**:

> **抽样取代折算**:dfs 中未知抽牌只计数(`drawn += 1`)经 `exp_per_draw`
> 进期望注记 face_exp——那是"当回合斩杀线"的正确语义。rollout 中未知抽牌
> **必须真实抽样入手**(从剩余牌表无放回抽,塞进 hand),禁用期望折算通道。
> 两者共用 play(),分歧只在调用方如何处理 known_draws 耗尽后的抽牌。

- **牌序抽样**:开局一次性生成剩余牌表的随机排列(种子可控,复现钉子);
- **每回合推进**:我方回合 +1 自然抽、费上限 +1(后手硬币按实际);
- **行动策略(1..K−1 回合)**:脚本化领域策略——养费/下引擎/过牌优先,
  **绝不打出启动组件**。策略偏倚是本设计最大的效度威胁,由 §6 轨迹层
  校准兜住(模拟轨迹分布 vs 真实 material 回合快照分布不符 → 校准失败,
  降级);
- **对手回合**:只做一件事——按存活曲线不干预我方(对手段对留牌无信息量,
  自闭前提;敌方血甲变化在启动谓词的分布里体现)。

## 4. 启动谓词

- 判定:第 K 个我方回合,`best_line(state, pieces, board_atk, enemy_total)`
  的 `total ≥ enemy_total`(dfs.py 现成 lethal 语义,零新引擎);
- **enemy_total 取固定血甲档位表**(2026-09-15 用户增补):默认
  `(26, 30, 40, 48, 56)`,产品侧(advise)按档逐档判定、默认档 30,
  对手职业≈选档(叠甲/恶魔猎手等),口径保守且语料无关;校准侧
  (calibrate)仍用真实敌方血甲曲线——验证必须对现实,不对档位表。
- 首个 `lethal=True` 的 K 记为启动回合,rollout 输出 P(启动≤K) 曲线。

## 5. 统计纪律

- **同牌序配对比较(CRN)**:每个抽样牌序上枚举全部 2ⁿ(n≤5,≤32)keep 集,
  集与集的差值共用同一随机源,方差远小于独立采样——这是"留 A 是否优于
  留 B"这类边际问题的正确统计形态;
- 量级:1k 牌序起步(p≈0.5 时 SE≈1.5%,CRN 下差值精度更高),`sim_orders`
  可调;性能钉子沿用 test_planner 的 worst-case 100ms 纪律,全量 1k×32×K
  必须分钟级内(超出=策略/谓词有性能回归,硬失败);
- **组合维度输出契约不变**(v3 §5.3 原样):score(set)=P_win(set),
  per_card_marginal / pair_synergy / anti_synergy / reject 全部由 2ⁿ
  打分表组合而来,零额外推理——模拟器只是把"打分"的实现从基座拟合
  换成频率计算。

## 6. 自验证 = 三层一致性检验(vs 真实语料)

"设计大量数据自我验证"的严格形态:**合成→合成的自洽只验证模拟器无 bug;
合成→真实的三层一致才验证模拟器无偏。**

| 层 | 检验 | 数据面 | 失败动作 |
|---|---|---|---|
| 轨迹层 | 模拟 mana/手牌数/已抽数的 K 回合分布 vs material 回合快照同口径分布 | 60 局当前 schema 重放(223 行 snap 为旧口径,material_v2 落地后刷新) | 校准失败 → 模拟器禁用,降级 TabPFN |
| 启动层 | P(启动≤K) vs 真实局"首个可斩回合"频率(语料重放逐回合跑 best_line 标注) | 同上 | 同上 |
| 结果层 | P(胜│启动) ≈ 1;启动却输的局逐个列出归因(冰甲?破坏?血甲分布尾?) | 85 局 | 谓词保守化(血甲分位上移/加例外清单) |

三层全部通过才允许模拟器系数上线(上线门槛复用 v3 §6 的 distill_min_agree
机制:蒸馏近似 vs 模拟器全量枚举的 top-1 一致率 ≥ 0.90)。

## 7. pieces 完备性铁律(与 live 斩杀线语义的显式分歧)

live 斩杀线上 `Piece` 缺失走 inert 诚实降级(只按费,uncovered_n 计数)——
那是**信息不足时的诚实**。模拟器语境下 inert = **系统性失真**(抽牌引擎/
减费/法强缺失会让 rollout 轨迹整体偏离),降级不诚实。故:

> 模拟器初始化时对牌表全量做 pieces 完备性检查(含可预期的衍生牌),
> 任何 `(cid, cost)` 无 pieces 或 `uncovered_n > 0` → **硬失败**,该卡组
> 模拟器不启用,级联降级。测试钉死。

## 9. 测试矩阵(增补,v3 §10 之上追加)

| 层 | 断言 |
|---|---|
| rollout 纯函数 | 同种子同结果;自然抽/引擎抽/减费/法强语义与 play() 契约一致 |
| 抽样纪律 | rollout 路径出现 face_exp/期望折算 → 失败;未知抽牌入手可追溯 |
| 启动谓词 | 已知小局面上 lethal 判定与手算一致;血甲分位三档单调 |
| pieces 完备 | 缺 pieces 的卡表 → 硬失败(不降级不告警后继续) |
| 校准 | 三层一致性的夹具钉子;任一层失败 → 降级路径可观测 |
| CRN | 同牌序下 keep 集两两差值与手算一致;2ⁿ 表完备 |
| 零变化 | mulligan_sim=false 输出与 v3 路径逐字节一致 |
| 最小可信 | two_games 夹具的真实局:模拟器复现实际发生的启动/未启动与实际留牌的 P_win 排序方向 |

## 11. 明确不做(增补)

- 不做对手行为模型/自对弈博弈(只取敌方数值分布——自闭前提的边界内求解);
- 不做通用多卡组模拟器(只服务 0 变化卡组,多卡组=每卡组一份牌表+校准,
  无通用化抽象,不为单次使用做抽象);
- 不改变 live 责任链形态与零 torch 条款;
- 不做 DT/CFR/RL 迭代策略改进(2026-09-15 可行性裁定:数据量级与无引擎
  双重不匹配,归档于当次讨论,不再复议)。
