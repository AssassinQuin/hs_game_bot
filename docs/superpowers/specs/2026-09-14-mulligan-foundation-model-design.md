## 0. 目标与非目标

**目标**：用小基座模型（tabular foundation model）重做留牌训练，吃进此前未用的信号
（换牌后换入牌、逐回合我方抽牌、对手英雄、我方卡组、场面），输出不止"留哪张"而是
**组合维度结论**："A+B 一起留"、"C 与 D 不宜同留"、"E 不留"。

**非目标**：
- 不做 LLM 微调（91 局样本量差 2 个数量级，实时推理也不允许）；
- 不改实时军师的责任链形态（store→analysis→render 环节与开关机制不动）；
- 不引入 live 进程的重依赖（torch 只进训练侧/CLI 侧，监控线程零新增依赖）。

## 1. 数据可用性（2026-09-14 盘点，91 局语料）

| 信号 | 现状 | v3 获取方式 |
|---|---|---|
| 换牌后换入牌 replaced_in | meta 覆盖 **0/91**（旧导出缺字段） | 原始切片重放推导：留牌决定→我方首回合开始之间的我方抽牌（store `MulliganState.replaced_in` 逻辑已有） |
| 每回合我方抽到的牌 | 未采集 | material 回合快照相邻差分 + 重放 draw 事件双通道，取并集 |
| 对手英雄/职业 | meta 74/91 | 事件流英雄 CLASS 补全（`_scan_hero_classes` 已有）→ ~100% |
| 我方卡组构成 | decklist 91/91 | 现有 `deck_features`（曲线/规模/类型/引擎密度/低费法术） |
| 场面（双方血甲/场攻/嘲讽/手牌结构） | material 逐我方回合快照已有（51 局/223 行） | 现有 `states.snapshot`/`flatten` |
| 对局胜负 | 91/91 | 现有 |

## 2. 架构：两阶段 + 标签蒸馏

```
原始切片重放(material_v2) ──► 回合行(快照+drawn_this_turn) + 决策行 + 结果行
        │
        ▼
 ① Q模型(基座): 第K回合局面 → P(胜)          [全信息合法: 回合K服务]
        │  作为低噪声标签(蒸馏)
        ▼
 ② 留牌评分器(基座): 决策时特征 → 0.5·胜负 + 0.5·Q₁₎₃   [无泄漏: 只用决策时信息]
        │  训练时蒸馏成系数表
        ▼
 ③ live 军师: per-card 增益 + pair 协同系数查表(毫秒, 零 torch)
```

**防泄漏纪律**（铁律，测试钉死）：
- Q 模型的特征允许含未来信息（换入牌/逐回合抽牌/场面）——它在第 K 回合服务，
  那时这些信息已经发生；
- 留牌评分器的特征**只允许决策时可得**：起手 offered、候选留集、对手职业
  （留牌阶段英雄已揭示）、先后手、卡组构成。任何决策后字段进特征 = 测试失败；
- 蒸馏标签 `y = 0.5·result + 0.5·Q(game|K=3)` 是本局已实现的量，训练用合法；
  Q 未过门控时自动退化为纯 result。

## 3. 素材扩展（material.py → material_v2.jsonl）

每局重放产出三类行（沿用 `_replay_slice` 管线扩展）：

- **决策行** `{"row": "mulligan", "game": …, "offered": [cid], "kept": [cid],
  "replaced_in": [cid], "coin": 0/1, "opp_class": "PRIEST", "deck_agg": {…}}`
- **回合行**（现有）+ 新增 `"drawn_this_turn": [cid]`（相邻快照手牌差分，
  与重放 draw 事件取并集；对手回合不产行，现状不变）
- **结果行** `{"row": "result", "game": …, "result": 0/1}`

Q 样本锚点 = 回合行本身（`turn ∈ {2,3,4}` 的我方回合行带上该局 result 即是），
不引入新结构。

统计口径：51 局 × 3 个 K ≈ 150 行 Q 样本；91 局决策样本（v2 的 LR 样本同源）。

## 4. Q 模型（阶段一）

- 特征 = `states.flatten`(K 回合快照) + 前 K 回合抽牌聚合(抽到的低费法术数/
  引擎件数/曲线覆盖) + 换入牌聚合 + 对手职业 onehot + `deck_features`
- 标签 = 对局胜负；训练 = 基座 in-context（无 epochs）
- 评估 = **组级（按局）时序留出**（`_game_level_split` 同款纪律），AUC ≥ 0.55
  过门控才作为蒸馏标签源；不过门 → 阶段二标签退化为纯胜负（不阻塞）
- 服务点：阶段二标签 + 未来 T2（play_ai 世界节点排序）复用同一模型

## 5. 留牌评分器（阶段二）

### 5.1 特征 schema（决策时可得，定长追加式）

| 组 | 内容 |
|---|---|
| 起手 | offered 在卡组词表内 onehot（vocab=卡组 30 卡，稳定小词表） |
| 候选集 | 留牌 onehot + 留牌张数 |
| 曲线 | 1/2/3 费各自"有牌可出"覆盖位、留集总费、低费(≤2)法术数 |
| 引擎 | 留集中引擎件数（prior engine 词表）、留集与卡组引擎密度比 |
| 协同 | 候选集内 pair 计数（LR_PAIR_SUPPORT 共现筛选后的 pair 列表） |
| 上下文 | 对手职业 onehot(11) + 先后手 |
| 卡组 | `deck_features`（现有尾部段，布局不变） |

### 5.2 标签与打分

- `y = 0.5·result + 0.5·Q₁₎₃`（Q 门控通过时；否则纯 result）
- **训练行 = 每局一行**（特征含该局真实留集，标签是该局结果）——留集是特征、
  结果是标签，模型从跨局变异中学"留什么导向赢"。反事实候选集**只在推理端
  枚举**（给未发生的留集复制同标签会向其注入假信号，禁止——泄漏纪律的
  数据侧姊妹条款，测试钉死）
- 推理：对当前 offered 的 2ⁿ 候选集（n≤5，≤32 集）批量基座打分，毫秒级

### 5.3 组合维度输出契约（机读事实，措辞归 render——项目铁律）

| 字段 | 定义 | 渲染语义 |
|---|---|---|
| `keep` | 最高分候选集 | "留 A、B、C" |
| `per_card_marginal[c]` | score(best) − score(best∖{c}) | "拍卖师 边际 +12%" |
| `pair_synergy[(a,b)]` | score(同留) − score(只留a) − score(只留b) + score(都不留) | "拍卖师+月火 同留 +5%" |
| `anti_synergy[(a,b)]` | pair_synergy < −0.02 且 a,b ∈ offered | "滋养与拍卖师不宜同留" |
| `reject[c]` | c ∉ keep 且单独边际 < 0 | "换 X" |

pair 集合限定在 offered 内（≤10 对），全部由 2ⁿ 打分表组合而来，零额外推理。

### 5.4 论证附录：拆行合法性与样本量算术

> 背景：语料仅 91 局时，自然直觉是"一局拆成单卡/双卡/…/≤4 张组合就能得到很多行"
> （含"起手组合 × 对手英雄胜率"、"从后面抽到的牌反推起手该留什么"）。
> 本节把账算清并给出拆行合法性判据，钉死 §5.2 禁令的论证，
> 同时记录该直觉中合法且值得做的变体。

**判据：一局拆多行是否合法，取决于每行的 (特征, 标签) 是否为真实共现的观测。**

| 拆法 | 标签来源 | 判定 |
|---|---|---|
| Q 行：第 K 回合真实手牌 + 该局胜负 | 真实共现（局面真实存在、结果真实发生） | ✅ 合法；锚点扩到全部我方回合可至一局 ~8 行（§4 现取 K∈{2,3,4}，扩展为候选改进） |
| 起手"含卡/组合→胜率"条件统计 | 真实共现（卡确实在起手出现过） | ✅ 合法但只是描述统计：做报告/先验，**不做训练标签** |
| 反事实留集行：给未发生的留集复制本局胜负 | 标签属于另一宇宙 | ❌ 非法（§5.2 禁令本体，测试钉死） |
| 模拟反事实行：候选留集→超几何抽样换入→推演→Q 打分 | 标签来自 Q 预测而非复制现实 | ✅ 合法但以 Q 过 §4 门控为前提；语料过百后的二期素材源 |

**样本量算术（91 局、先手 3 张/后手 4 张即均值 ~3.5 张、30 卡卡组）：**

| 粒度 | 每格期望观测局数 | 胜率估计 95% CI |
|---|---|---|
| 单卡"在起手→胜率" | 91 × 3.5/30 ≈ 10.6 | ±30pp |
| 双卡组合 | 91 × C(3.5,2)/C(30,2) ≈ 0.9 | 无意义 |
| 组合 × 对手职业 | ≈ 0.1 | 纯噪声 |

推论：
1. 组合行数翻十倍，信息上限仍是 91 个胜负比特。复制标签的行是系统性错误而非
   随机噪声：同局内留集怎么变标签都不动 → 局内对比（留牌建议真正需要的信号）
   方差为零 → 模型转学游戏级混杂（"什么对局会赢"）而非"留什么导向赢"；
2. 单卡格 ~10 局撑不起留牌效应量（±5pp 量级）——这是裸统计表的天花板，
   也是用特征化基座做池化的理由（费用/类型/引擎等共享特征跨卡跨职业借力，
   模型本身就是池化设备）；
3. "起手条件胜率表"（HSReplay Mulligan Win Rate 同口径）进 report/render 契约：
   带样本数与置信区间展示，Beta 收缩后可作评分器/Thompson 先验；
4. "从后面抽到的牌反推起手"的合法形态 = Q 行（真实回合状态）+ 模拟反事实
   （91 局 × 32 候选集 × 200 抽样宇宙 ≈ 58 万行，标签为 Q 预测）两条路；
   模拟通道需注意 Q 在模拟局面上的分布偏移，只做素材源、不做评估基准。

## 6. Live 集成：蒸馏系数（关键工程决策）

监控线程**不装 torch**（沿live 禁 TabPFN fit 的审计结论）。方案：

- **训练时**把基座对候选空间的打分蒸馏成可分解系数：
  `score(set) ≈ Σ_{c∈set} gain[c] + Σ_{pairs⊂set} syn[(a,b)]`
  （对训练语料的全部 offered × 候选集做最小二乘拟合，与现有统计表/pairs 同构）
- **live 军师**加载系数表，走现有 `best_keep_set` 管线毫秒出建议——
  推理层接口零改动，只是 gains/pairs 的来源从统计表换成蒸馏系数
- **CLI advise**（离线，允许 torch）：基座全量枚举 + 组合维度输出全字段
- 上线门槛：蒸馏近似 vs 基座全量枚举的 top-1 集合一致率 ≥ 90%（组级评估），
  低于则 live 回退统计表路径并告警

## 7. 基座选型与后端抽象

`scorer_backend: tabpfn_v2 | tabicl_v2`（config.yaml，训练侧配置）：

| 后端 | 定位 |
|---|---|
| **TabPFN v2** | 主力：≤10k 行甜点、CPU 秒级、pip 即装（现有 TabPFNWrap 扩展） |
| **TabICL v2** | 免费对照：BSD-3、2026-02、AutoGluon 默认，小数据互有胜负 |
| TabPFN-2.6 / 3 | 升级路径（语料上千后）：更强但需许可+GPU，本期不接 |

- 训练时**两个后端都跑**组级时序 CV 对照（各几秒），AUC 谁高谁产出蒸馏系数
  ——复用现有 `LR_AUC_GATE` 门控哲学：模型互不信任，指标说话；
- 现有三级级联保留为兜底：基座系数 → LR → 统计表（谁都可能在小样本上翻车）。

## 8. 配置与开关

```yaml
mulligan_v3: true          # 总开关; false 时输出与 v2 逐字节零变化(钉子测试)

distill_min_agree: 0.90    # 蒸馏系数上线门槛(top-1 集合一致率)
```

Thompson 探索不变（继续走统计表后验，探索局与 v3 并存）。

## 9. 评估与回测

1. **组级时序 CV 对照表**（report 输出）：TabPFN v2 / TabICL v2 / LR / 统计表
   的 AUC + LogLoss，按局分组不泄漏；
2. 蒸馏一致率（§6）；
3. 回测：历史局上"模型最优集 vs 实际留牌"的 Q₁₎₃ 差值分布
   （建议方向是否系统性指向更优早期局面）；
4. 门槛未过的诚实降级路径各有钉子测试。

## 10. 测试矩阵

| 层 | 断言 |
|---|---|
